# March Madness Bracket Analyzer

> This file is loaded into every Claude session. Keep it lean and accurate.
> For how the workflow system works, see `docs/reference/`.

## What This Is
Python CLI + React web UI that runs 10,000 Monte Carlo simulations of the 2026 NCAA tournament. Uses logistic regression trained on 18 years of data (2008–2025), live Barttorvik metrics, injury adjustments, and momentum. Terminal output shows three bracket strategies with champion probabilities. The web UI adds interactive override and cascade recalculation.

## Stack
- **Backend**: Python 3.12+, pandas, numpy, requests, scikit-learn, rich, typer
- **Frontend**: React, TypeScript (strict), Vite — localhost only, no deployment
- **Data**: Barttorvik JSON API (free, no auth)

## Key Commands
```bash
pip install -r requirements.txt                                          # install Python deps
python scripts/build_historical_data.py                                  # one-time: build training CSV
python main.py run --bracket data/2026_bracket.json                      # terminal output
python main.py run --bracket data/2026_bracket.json --export all         # export CSVs
python main.py ui-export --bracket data/2026_bracket.json --sims 10000   # export JSON for web UI
cd ui && npm install && npm run dev                                      # start web UI at localhost:5173
python main.py upsets --bracket data/2026_bracket.json                   # upset alerts only
python main.py champion --bracket data/2026_bracket.json                 # champion probabilities
```

## Important Paths
- `src/fetch_data.py` — Barttorvik API fetcher (live metrics + momentum from fields 29/30/31)
- `src/model.py` — blended model: 60% logistic regression + 40% composite (ensures injuries always affect predictions)
- `src/bracket.py` — Monte Carlo engine (10k sims, 3 strategies) + `MonteCarloResults` + `get_ff_pairings()`
- `src/upsets.py` — multi-factor upset detection
- `src/injuries.py` — Barthag penalties with fuzzy team name matching
- `src/output.py` — terminal display + CSV/JSON/UI JSON export (`export_ui_json`)
- `ui/` — Vite + React + TypeScript SPA (bracket visualization, click-to-override, cascade)
- `ui/src/lib/cascade.ts` — client-side cascade recalculation using probability matrix
- `ui/public/data/bracket-data.json` — generated by `ui-export` command, loaded by React app
- `data/injuries.json` — manual injury entries (supports verified_clean, _comment dividers, fuzzy name match)
- `data/tournament_results.csv` — historical results 2008–2025 (1082 teams)

## Constraints
- All terminal output via `rich` — no bare `print()` calls
- Barttorvik is the sole data source — endpoint: `https://barttorvik.com/{year}_team_results.json` (works 2008–2026)
- All 68 team names must resolve to Barttorvik names — surface lookup failures clearly
- Model blends 60% logreg + 40% composite so injuries (Barthag adjustments) always have weight
- Final Four pairings: East vs West, South vs Midwest (via `get_ff_pairings()`, not JSON key order)
- Matchups with >90% win probability are flagged `locked` in UI JSON — UI prevents overrides
- injuries.json entries with null player/impact/status or verified_clean are skipped
- UI is localhost-only (Vite dev server), no deployment needed
- Frontend uses TypeScript strict mode, functional components, named exports

## Lessons
- Barttorvik HTML endpoints have JS browser verification — only JSON endpoints work for automated access
- `getadvstats.php` returns player-level data — use `{year}_team_results.json` for team rankings
- Fields 29/30/31 are recent-window AdjO/AdjD/Barthag — used for momentum
- Team name matching is fragile — `scripts/fix_team_names.py` + fuzzy matching in injuries.py
- Model gracefully degrades: trains on available features, falls back to composite if logreg fails
- Logreg trains on absolute advancement probability, not head-to-head — blending with composite compensates
- `_prob_cache` is on MonteCarloSimulator, not MonteCarloResults — pass simulator to `export_ui_json`
